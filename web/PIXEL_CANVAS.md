# Общее полотно

В Telegram весь фон главной является общим полотном. Баннер «мама-анархия» /
«пора рисовать на доске!» включает рисование на том же фоне. Расписание временно
скрывается, выбор цвета и круглая кнопка с галочкой появляются снизу. Масштаб вынесен
в отдельный блок слева по центру, админская кнопка — справа сверху. Полотно
обновляется автоматически, отдельной кнопки обновления нет. Возврат восстанавливает
расписание и положение прокрутки. Касание ставит клетку, перемещение и щипок
меняют камеру; колесо мыши увеличивает полотно. Клавиши со стрелками выбирают
клетку, Enter/пробел рисуют, Escape закрывает палитру или режим рисования.

Полотно имеет общие конечные границы: **128×256 клетки**, 32 768 клетки всего.
Это вертикальная область с пропорциями 1:2, выбранными для мобильного трафика.
Координаты X: -64…63, Y: -128…127. Центр — (0,0). На главной масштаб покрывает
весь фон экрана; при рисовании клетки увеличиваются до 24 CSS px. Масштаб не
меняет физический размер общего поля. Камера останавливается у края, граница
и полоса снаружи видны только в режиме рисования. Нижний край доступен выше
панели инструментов, верхний — ниже системных элементов Telegram. Все записи,
закрашивания, чтение области и запросы истории ограничены теми же границами
на сервере. Совпадение рисунка между разными телефонами сохраняется.

## Сервер

`pixel_canvas.py` и `pixel_canvas.wsgi` работают в отдельном WSGI-процессе,
не импортируют `app.py` и не открывают `database.db`. Их база:
`/var/lib/kkepik-pixels/canvas.sqlite3`, SQLite WAL. Переопределение пути:
`KEPIK_CANVAS_DATABASE`. Каталог должен принадлежать `www-data`, режим 750.

Глобальная настройка Apache: `ops/pixel-canvas-apache.conf`. Внутри каждого
VirtualHost до основной ссылки `/` подключается `ops/pixel-canvas-vhost.conf`.
Один общий демон обслуживает все домены. Очередь и время обработки ограничены;
занятая база возвращает 503 без долгого ожидания.

Все запросы требуют подписанный Telegram initData в `X-Telegram-Init-Data`.
ID аккаунта берётся исключительно из проверенной подписи. `POST /api/pixels/place`
принимает целые `x`, `y`, индекс `color` из общей палитры и `request_id`.
Проверка времени и запись выполняются в одной транзакции `BEGIN IMMEDIATE`.
Минимальный интервал зависит от онлайна: 250 мс до 4 человек, 500 мс
при 5–8, 1000 мс от 9 человек;
вкладки, процессы и перезапуски не сбрасывают лимит. Пиксели не накапливаются.
Повтор последнего `request_id` с тем же содержимым возвращает результат без
повторной записи. Побеждает последняя принятая сервером запись, владельцев клеток нет.

`GET /api/pixels/state?x0=…&y0=…&x1=…&y1=…&since=…` возвращает снимок области
или её изменения после указанной ревизии. Максимальная область — 65 536 клеток.
Снимок и курсор читаются в одной транзакции. Таблица pixels хранит последнее
состояние клетки; отдельная таблица canvas_history сохраняет историю для таймлапса.

## Клиент и проверка

`static/js/pixel_state.js` хранит конечное полотно целиком (не больше 32 768
клеток), общий курсор чтения и один активный запрос. Первый ответ — полный
снимок, дальнейшие — изменения по ревизии. Сдвиг камеры и масштаб не запускают
новые запросы и не отменяют чтение: уже загруженные клетки видны сразу, а
опрос продолжается во время движения. Отрисовка выбирает только видимые
клетки, с отдельным быстрым проходом для редкого рисунка.

Запоздавшие ответы после отмены, offline, скрытия или pagehide игнорируются.
Подтверждённые записи новее снимка сохраняются, а подтверждение записи не
сдвигает курсор чтения. Стирания хранятся как ревизионные tombstones. Ответ
проверяется целиком до изменения кеша; восстановление базы с более ранней
ревизией сбрасывает старое состояние. Веб-админка использует тот же механизм.

`static/js/pixel_canvas.js` загружается после основных скриптов и запускается
после bootstrap расписания. В обычном режиме обновления раз в 5 секунд, на слабой
сети раз в 15 секунд; при рисовании раз в секунду. Скрытие приложения и потеря
сети останавливают опрос. Ошибки включают задержку повторов до 30 секунд.
Сбой доски не блокирует расписание. API не попадает в кеш service worker.

Серверные проверки запускаются без основной базы:

```sh
venv/bin/python -m unittest tests.test_pixel_canvas -v
node tests/pixel_state.test.cjs
node --check static/js/pixel_state.js
node --check static/js/pixel_canvas.js
```

Для браузерной проверки используются настоящие шаблон, CSS и JS, одноразовая
база и тестовая Telegram-подпись. Проверяются светлая/тёмная темы, ширины
390 и 320 px, секундный лимит, перемещение и щипок без рисования, отсутствие
перехода в старый `/test`, потеря сети и возврат к расписанию. Тестовые изображения
и записи не добавляются в настоящее полотно.

## Администратор и таймлапс (29.09.2026)

Палитра — 16 приглушённых цветов; индексы существующих рисунков сохранены.
Главная показывает полотно через вуаль с непрозрачностью 0,63 вместо 0,87.
Вход в рисование увеличивает клетки до 24 CSS px, раскрывает Telegram Mini App
и запрашивает fullscreen для клиентов 8.0+. В старых клиентах остаётся expand.
Жест закрытия Telegram временно отключается; при выходе восстанавливается.
Касание ставит пиксель, удержание 320 мс включает кисть с серверным адаптивным интервалом,
движение до удержания перемещает камеру. Два пальца перемещают и масштабируют.
Лупа над пальцем показывает точную клетку; доступны кнопки +/−.

`/admin/canvas` доступен через карточку «Общее полотно» в `/admin`.
Выделение прямоугольника позволяет закрасить его выбранным цветом или стереть.
Лимит одной операции — 65 536 клеток, это ограничение запроса, не размер доски.
Отрицательные координаты поддерживаются; поля X/Y перемещают камеру.

Telegram-аккаунт **1084693264** получает кнопку «Инструменты админа» непосредственно
на полотне после подтверждения прав сервером. Быстрая кисть, ластик (1/3/7 клеток)
и выделение области обходят секундный лимит только через защищённые admin API.
Обычный режим этого аккаунта и все остальные участники соблюдают адаптивный лимит.

`/api/pixels/admin/state`, `/admin/fill`, `/admin/history` проверяют подписанный
`X-Telegram-Init-Data` и конкретный ID на сервере, либо короткоживущий
`X-Canvas-Admin-Token` из авторизованной веб-админки. URL, JSON-поля с ID и
отображение кнопок не дают прав. Чужой Origin отклоняется, CORS не включён.
Веб-токен подписан отдельным случайным ключом `/var/lib/kkepik-pixels/admin.key`
(root:www-data, 0640, вне web root), имеет отдельный scope и срок 15 минут.
`GET /admin/canvas/token` выдаёт его только при `superadmin_authenticated`;
обычная VPN-админка не подходит. Страница и токен не кешируются, имеют CSP и
запрет встраивания во фрейм. Не копируйте и не публикуйте ключ или initData.

Каждая принятая правка теперь атомарно добавляет событие в `canvas_history`.
Закрашивание прямоугольника — одно компактное событие. Стирание оставляет
ревизии в состоянии клеток, чтобы его увидели клиенты с инкрементальной загрузкой.
Удалённые рисунки доступны лишь в защищённой истории администратора.
Первое включение истории сохраняет текущий рисунок как начальный кадр;
изменения до этого момента восстановить нельзя. История сохраняется после
перезапуска; автоматической очистки нет. Вместе с полотном её нужно резервировать,
следить за местом в `/var/lib/kkepik-pixels`.

В веб-админке кнопка «Всё полотно» и максимальное отдаление показывают все
128×256 клеток с отступом от краёв. Обзор сохраняется при изменении размера
окна и доступен во время таймлапса. Если нет выделения, запуск таймлапса
из такого обзора загружает историю всего полотна.

Кнопка «Таймлапс» воспроизводит выбранный участок или видимую область:
логарифмический регулятор от 1 до 10 000 правок в секунду, быстрые значения
10/60/240/1 000/10 000, пауза, ползунок для перемотки и дата кадра. Изменение
скорости применяется без перезапуска. На обработку правок в одном кадре
отводится до 8 мс (одна операция применяется целиком); при тяжёлых заливках
фактическая скорость ограничивается производительностью браузера.
Начальный снимок показывается сразу, а не как выдуманная последовательность правок.
История читается страницами по 2000 событий с фиксированной верхней границей.
Просмотр не меняет живое полотно. «К полотну» возвращает модерацию.

## Авторство и конечные границы (29.09.2026)

`GET /state` возвращает `bounds` вместе с палитрой. Главная подбирает масштаб
по пропорциям экрана, редактор позволяет увеличивать и перемещать поле внутри
его границ. Полотно не повторяется плитками и не создаёт новые клетки за краем.
Админская кисть обрезается по краям, выходящие за границу серверные запросы
отклоняются. Существовавшие на момент обновления рисунки помещаются в поле.

Каждая новая принятая правка сохраняет `actor_id` (Telegram ID), `actor_name`,
`actor_username`, `actor_kind` и время. Поля автора заполняются только из
проверенного Telegram initData. Присланные в JSON ID/имя/username игнорируются.
В `pixels` хранится автор последней правки клетки, в `canvas_history` — автор
каждого изменения, включая перекраски, быстрые админские правки и стирание.
Веб-админка записывается отдельно как `web_admin`, без выдуманного Telegram ID.
Автор — создатель конкретной правки, он не получает права собственности на клетку.

Миграция добавляет колонки без удаления пикселей и истории. Для старых записей
автор восстанавливается только если сохранённый последний запрос игрока точно
совпадает по ревизии, координатам и цвету. Оставшиеся записи имеют `unknown`,
интерфейс показывает «Автор не записан». Старые админские действия не приписываются
Telegram-владельцу автоматически.

`GET /api/pixels/admin/pixel?x=…&y=…` возвращает последнее состояние клетки
с автором и до 20 последних событий, затронувших её. Доступ защищён тем же
серверным админским механизмом. Обычный `state` сохраняет компактный массив
[x,y,color,revision] и не раскрывает личности участников.

В веб-админке «Автор» включает просмотр клетки и списка её правок, в Telegram
эта кнопка находится внутри инструментов владельца. Просмотр ничего не рисует.
Таймлапс показывает автора текущей правки рядом со временем; начальный кадр
помечается как начальное состояние, а не как действие одного пользователя.

Дополнительная проверка авторов и миграции:

```sh
venv/bin/python -m unittest tests.test_pixel_canvas tests.test_pixel_canvas_admin tests.test_pixel_canvas_authorship -v
```

## Онлайн, срок ивента и баны (30.09.2026)

Счётчик слева сверху показывается при онлайне от 5 человек включительно и учитывает
уникальных пользователей **во всей мини-аппке**,
включая расписание, поиск, игры, посещаемость и VPN. `miniapp_presence.js`
подключён ко всем страницам с Telegram SDK и работает независимо от полотна.
Публичный сайт без подписанного Telegram initData не регистрируется.
`POST /api/pixels/presence` принимает случайный ID сессии, возрастающий `sequence`
и флаг `active`; Telegram ID берётся из проверенной подписи заголовка.

Активная страница отправляет heartbeat каждые 15 секунд; скрытие, Telegram
`deactivated` и уход со страницы отправляют `active:false` с `keepalive`.
При обрыве соединения пользователь исчезает не позднее чем через 35 секунд
после последнего heartbeat. Несколько вкладок одного человека считаются один
раз; закрытие одной не исключает остальные. Сохранённый номер последовательности
не позволяет старому heartbeat воскресить уже закрытую сессию. Неактивные записи
очищаются через 5 минут; на аккаунт хранится не больше 16 сессий.

`POST /api/pixels/admin/event/start` один раз сохраняет серверное время старта и
окончание ровно через 7×24 часа. Повторный вызов и перезапуск не продлевают срок.
До явного включения срок отключён, что позволяет безопасно обновить схему.
После окончания обычный `/place` возвращает 423 без изменения клеток,
кулдауна или истории. Проверка срока выполняется после получения write lock
в той же транзакции, что и запись. Просмотр, таймлапс и `/admin/fill` сохраняются.
Клиент использует оставшееся серверное время и монотонные часы, отключает цвет
и кисть при окончании; дата окончания показана рядом с онлайном.

В инструментах Telegram-владельца «Автор» позволяет забанить/разбанить автора
выбранной клетки. В веб-админке доступны та же кнопка и список «Баны на полотне»
с разбаном. `POST /api/pixels/admin/ban` принимает `telegram_id` и `banned`;
`GET /api/pixels/admin/bans` доступен только владельцу или веб-админу с
проверенным токеном. Присланные права/ID администратора не учитываются.
Владельца 1084693264 забанить нельзя. Все изменения бана записываются в
`canvas_moderation` с серверным временем и проверенным автором действия.

Баны сохраняются в SQLite после перезапуска. `/place` проверяет бан внутри
`BEGIN IMMEDIATE`, прежде чем проверять идемпотентный повтор и кулдаун: даже
прямой запрос заблокированного аккаунта получает 403. Ответы состояния включают
собственный статус бана и монотонную ревизию модерации, чтобы старый снимок,
включая сделанный в ту же миллисекунду, не отменил более новый запрет на клиенте.
При бане расписание и другие разделы работают, пользователь продолжает
учитываться в онлайне. Рисование показывает отдельный экран с текстом
«Вот ты и попался, рисователь молотов, сюрикенов и прочей крутой фигни.»,
кнопкой «К расписанию» и локальным изображением `static/img/canvas-ban.jpg`.
Источник картинки: https://i.pinimg.com/736x/65/74/b3/6574b31552981d035ee0a45292898152.jpg

## Адаптивная скорость и откат пользователя (30.09.2026)

Скорость задаёт сервер: до 4 человек — 250 мс, 5–8 — 500 мс, от 9 — 1000 мс.
Для выбора скорости учитываются уникальные аккаунты с активным heartbeat и
принятыми пикселями за последние 35 секунд, а также текущий рисующий аккаунт.
Это не позволяет клиенту ускорить рисование, отключив heartbeat. Видимый счётчик
по-прежнему показывает активные страницы мини-аппки; недавнее рисование влияет
только на безопасную скорость. После ухода игроков ускорение может задержаться
до 35 секунд. Поддельные `online_count`/`cooldown_ms` в JSON не учитываются.

В `canvas_players.cooldown_ms` сохраняется интервал принятого пикселя. Изменение
онлайна, новая вкладка и перезапуск не сокращают уже выданный интервал. Новая
скорость действует со следующего принятого пикселя. State и ответы placement
передают текущую скорость, оставшееся время и ревизию последней записи игрока;
клиент не позволяет старому ответу продлить интервал более новой подтверждённой
записи. Полоса ожидания и кисть используют серверные значения. Админские API
сохраняют быстрый режим, баны и окончание ивента остаются обязательными.

В мини-аппке «Автор» → «Откатить правки автора» сначала показывает количество
записанных правок и восстанавливаемых клеток на всём полотне; второй клик
подтверждает операцию. В веб-админке это доступно через автора клетки, кнопку
«Откат» в списке банов и блок «Откат пользователя» по Telegram ID.

`GET /api/pixels/admin/rollback?telegram_id=…` выполняет только предварительную
проверку и возвращает `through_id` — границу записанной истории. `POST` того же
endpoint принимает целые `telegram_id`, `through_id` и уникальный `request_id`.
Оба запроса требуют защищённых админских прав и запрета чужого Origin.
Повтор одного request_id идемпотентен и привязан к автору, цели и границе истории.

Откат отменяет записанные player/admin-правки Telegram-пользователя до указанной
границы. Начальный baseline, неизвестные авторы и последующие правки остальных
участников сохраняются. Новые правки самого пользователя после проверки также
сохраняются: при необходимости его можно сначала забанить. Рисунок до начала
записи истории восстановить невозможно. Бан и таймеры игрока откат не меняет.

Сервер пересчитывает нужные клетки из истории в одной `BEGIN IMMEDIATE`
транзакции. `canvas_rollback_edits` помечает отменённые события, а
`canvas_rollbacks` хранит операцию и подтверждение для безопасного повтора.
При следующих откатах уже отменённые события и служебные кадры восстановления
не воспроизводятся — откат второго пользователя не воскресит действия первого.
Память ограничена конечным полотном; события читаются потоком.

Оригинальные события не удаляются. Восстановленные клетки получают одну новую
ревизию, записи `source=rollback` с проверенным администратором, временем и
ревизионными tombstones для пустых клеток. Клиенты получают их обычным state;
таймлапс объединяет клетки одной операции в один мгновенный кадр, включая
операции, чьи записи загружены несколькими страницами истории.

```sh
venv/bin/python -m unittest tests.test_pixel_canvas_rollback_pacing -v
node --test tests/pixel_state.test.cjs tests/miniapp_presence.test.cjs
```

Обновление 20260930-4 внедрено на действующем сервере. Прошли 106 серверных
и 25 JavaScript-проверок, включая сравнение последовательных откатов с независимыми
стеками правок каждой клетки. Нативный мобильный браузер проверил три скорости,
предварительный просмотр и применение отката в обеих админках, сохранение правок
после границы предварительной проверки и единый кадр восстановления в таймлапсе.
На действующем полотне проверены права и выполнен только GET предварительного
расчёта, без применения отката и без тестовых пикселей. Срок текущего ивента сохранён.

## Чат полотна (30.09.2026)

Кнопка облачка над галочкой открывает нижнюю панель около 42% высоты экрана.
В закрытом виде рядом с кнопкой отображается спокойный счётчик новых сообщений
(до «99+»), без звуков, всплывающих текстов и автоматического открытия.
Первое посещение начинает отсчёт с текущей истории. Прочитанным считается
показанный конец списка; собственные и скрытые сообщения не увеличивают счётчик.
Положение полотна сохраняется. Пока открыт чат, рисование приостановлено;
клавиатура открывается только при выборе поля. Назад / Escape сначала закрывают
чат. Учтены мобильная клавиатура, безопасные отступы и светлая/тёмная тема.

Одна общая история на текущий ивент, последние 50 сообщений. Только текст и
эмодзи, не более 200 Unicode-символов, без активных ссылок и вложений. Новые
сообщения принимаются раз в 5 секунд и не более 6 в минуту на проверенный
Telegram ID; отклонённая фильтром попытка тоже запускает интервал в 5 секунд.
После окончания ивента остаётся чтение и модерация.

### API и хранение

- `GET /chat/messages?after=<прочитанный ID>` — последние 50 видимых сообщений,
  согласованный курсор, ревизия модерации, собственный статус и интервал.
- `POST /chat/messages` — `{text, request_id}`; Telegram launch проверяется по
  заголовку. Повтор одного ID с тем же текстом возвращает квитанцию, не создаёт
  дубль. Изменённый текст под старым ID получает 409.
- `GET /admin/chat/messages`, `GET /admin/chat/bans` — защищённые чтения.
- `POST /admin/chat/hide` — `{message_id}`; сообщение скрывается из всех списков,
  но остаётся в записи для истории модерации.
- `POST /admin/chat/ban` — `{telegram_id, banned}`; отдельный запрет писать в чат.
  Полотно, расписание и остальные функции не меняются. Владелец защищён от бана.

Админские действия доступны владельцу 1084693264 с проверенным заголовком
Telegram или веб-админке с ограниченным подписанным токеном. Обычная выдача
не раскрывает чужие Telegram ID; имена и сообщения вставляются через textContent.
Привилегии нельзя получить из JSON или URL. Изменяющие запросы отвергают чужой
Origin. Все выдачи private/no-store, без CORS.

Добавлены только таблицы в изолированной БД полотна: canvas_chat_meta,
canvas_chat_messages, canvas_chat_senders, canvas_chat_bans,
canvas_chat_moderation. Подписанный автор, идемпотентность, интервал и бан
проверяются внутри BEGIN IMMEDIATE; скрытия и баны имеют отдельную ревизию
и аудит. Общая ревизия пикселей и история таймлапса не затрагиваются.

Закрытый чат получает только числовую сводку с существующим /state
(параметр chat_after). Дополнительного опроса закрытого чата нет. Открытый
список обновляется при новой ревизии и раз в 5 секунд; не более одного чтения,
тайм-аут 8 секунд, отмена на закрытии/уходе/потере сети, ограниченный backoff.
Старые снимки не отменяют новую модерацию. Список и непрочитанное считаются
в одной read-транзакции; подсчёт непрочитанного ограничен 100 записями.

### Строгий фильтр

`pixel_chat_filter.py` проверяет сообщения на сервере, включая владельца.
Нормализация NFKC/NFKD, casefold, диакритики, невидимые и направляющие символы,
транслит RU/EN, визуальные замены букв, цифры/leet, повторы, разделители,
эмодзи внутри слова и отдельные замаскированные формы. Предусмотрены русский
мат и грубые оскорбления, английские ругательства, нацистские лозунги, имена,
символы и коды, расистские оскорбления и отдельные призывы. Отклоняются и
нейтральные цитаты этих запрещённых выражений: фильтр намеренно строгий.

Локальный словарь 1 598 похожих символов получен из Unicode Security 16.0.0:
[data/chat_confusables.json](data/chat_confusables.json), исходный URL и SHA-256
записаны рядом с данными. Лицензия — data/UNICODE-LICENSE.txt.
Основы нормализации: [UTS #39](https://www.unicode.org/reports/tr39/) и
[Python unicodedata](https://docs.python.org/3/library/unicodedata.html).
Загрузка словаря производится один раз при импорте; внешних сетевых проверок
и отправки сообщений сторонним сервисам нет.

Разрешения для обычных слов применяются только к целому слову с ограниченными
окончаниями, не снимают запрет с соседнего мата. Проверены «рубля», «корабля»,
«употреблять», «страхуйся», «жидкость», «finish it», координаты и обычные фразы
про рисунки и расписание. Оскорбительное имя заменяется на «Участник».
Полностью исключить все новые шифры, контекстные оскорбления и ложные
срабатывания словарным фильтром нельзя; удаления и отдельный бан остаются
доступны владельцу прямо в чате и в веб-админке.

Проверки: tests/test_pixel_chat.py — Unicode/обходы и обычные фразы, авторство,
приватность ID, XSS как текст, непрочитанное/скрытия, идемпотентность, конкурентные
вкладки, интервал/бурст, отдельные баны, Origin/доступ и завершение ивента.
Нативный Chrome проверяет мобильные уведомления, чтение, отсутствие опроса в
закрытом состоянии, отказ фильтра с сохранением текста, Back/Escape, инструменты
владельца, маленький экран, клавиатуру и веб-модерацию.


## Finished-event results (2026-10-08)

The former drawing screen opens the frozen full-board replay once the event has finished. The default speed is 3,000 logical changes per second; the slider covers 1–10,000, with presets 1,000/3,000/10,000. Pause, backward/forward seek, fit-to-board, pinch/pan and the existing back controls remain available. The owner can switch to moderation and back without changing the replay archive.

`GET /api/pixels/replay` and `/api/pixels/replay/data?export_id=…` require verified Telegram launch data and a finished event. The archive omits author names, usernames and Telegram IDs. The gzip binary starts with `KKEPBR01`, then little-endian signed int32 records: history id, revision, time offset, x0, y0, x1, y1, color, source flag. Source flags are player=0/admin=1/baseline=2/rollback=3. Consecutive rollback rows with the same revision form one atomic playback step. SHA-256 and record count are checked before playback. The client loads the history once, uses a typed array and a small offscreen canvas, applies edits with a frame budget, and cancels animation when hidden or closed.

The frozen export is at `/var/lib/kkepik-pixels/replay/`; `current.json` points to its immutable version. `ops/export_pixel_replay.py` accepts a read-only SQLite snapshot, verifies that replaying all recorded edits reproduces every final pixel and erasure, produces the binary and a 768×1536 H.264 MP4 at 30 fps. MP4 playback uses 3,000 changes/second, a one-second opening and five-second final hold. Files in `/static/exports/pixel-battle-*.mp4` download with Content-Disposition attachment. The public video shows artwork only.

To regenerate after further moderation, first make a consistent SQLite backup, then run `venv/bin/python ops/export_pixel_replay.py SNAPSHOT.sqlite3`. The export keeps previous immutable versions for clients already playing them. The database, event deadline, history and users are never changed by export or public playback.

Validation: replay engine tests cover initial state, rectangles, erasures, atomic rollback, seek equivalence, frame budgets and truncated files. API tests cover authentication, event closure, archive traversal, read-only behavior and actual video generation. Native browser checks use the full 285,889-record archive and verify pause, seek, slider/presets, one history download, small dark screens, landscape and owner moderation.
